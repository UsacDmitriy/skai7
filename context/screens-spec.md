# Спецификация экранов — SKAI Unified Window

> Источник: анализ клиентских интервью + дизайн-исследование.
> HTML-мокапы: `ui/` (референсы для вёрстки).

---

## Экран 1: Карточка инцидента `/incidents/:id`

**P0. Главный экран.**

### Что должно быть:
- Левая зона: видео CAM-01 (ADAS ch1) + CAM-02 (DMS ch5), синхронный прогресс
- Центр: TelemetryChart — скорость и ускорение ±60 сек, маркер t=0; Leaflet-карта маршрута
- Правая зона: параметры события, блок причины, кнопки действий

### Два потока (критично):
1. **Есть видео** (`video_available=true`): два плеера + синхронная перемотка
2. **Нет видео** (`video_available=false` или `cam_dms_url=null`): placeholder + «Запросить архив»

### Блок причины (Фомин):
```
[😴 Усталость] [📱 Телефон] [🚗 Подрезали] [⚙ Техн. сбой]
```
Активный — подсвечен primary (#1E3A8A). Сохраняется в `POST /api/actions`.

### Кнопка звонка (Маслов):
`[📹 Позвонить через камеру]` — idle → connecting → `[🔴● 00:12]`

### Поля из реальных данных (v_incidents):
`id, alarm_label_ru, ts, vehicle_plate, speed_kmh, video_available,
 cam_dms_url (ch5), cam_front_url (ch1), risk_level, mileage_km`

Нет в данных, нужен mock/enrichment: `driver`, `vehicle_model`, `continuous_driving_min`

## Экран 2: Монитор `/monitor`

**P0. Операционный экран диспетчера.**

### Что должно быть:
- Список инцидентов с severity-бордером (слева)
- Leaflet-карта с маркерами ТС (центр)
- Детали выбранного инцидента (справа)
- Переключатель роли: [🏭 Логист | 🛡 Диспетчер | 🔒 Безопасник]

### Ролевой фильтр (Маслов):
- **Логист**: скрыть DMS_DROWSY, DMS_PHONE — только телематика
- **Диспетчер**: все события
- **Безопасник**: акцент на score и грубых нарушениях

### Дедупликация ТС (Маслов):
Одна точка на `unit_id`, не на alarm_id — решает проблему «5 точек вместо 3».

## Экран 3: Аналитический отчёт `/report`

**P0. Killer feature (Оздоев).**

### Четыре состояния:

**А — пустой:** NL-поле + пресеты («Покажи нарушения Иванова за 3 дня»)

**Б — подтверждение:** «Вот как я понял запрос» — водитель, период, тип данных, уверенность

**В-1 — отчёт по водителю:**
- DriverReportCard + KPI
- Таблица нарушений
- **Клик на строку → VideoPanel справа** (Оздоев killer feature)

**В-2 — отчёт по парку:**
- Список водителей / ТС с рейтингом
- Клик → мини-дашборд → «Открыть полный отчёт»

### Из реальных данных:
Нарушения = v_incidents отфильтрованные по vehicle_plate/дате.
Клик на нарушение → `cam_dms_url` или `cam_front_url` из той же записи.

## Экраны 4-8 (P1-P2)

### Экран 4: Лента событий `/` (P1)
Список всех v_incidents с фильтрами. КPI-бар сверху. Клик → `/incidents/:id`.

### Экран 5: Заявки `/tickets` (P1)
CRUD заявок из `output/actions.csv`. Статусы: новая/в работе/закрыта.

### Экран 6: Диспетчерский алерт `/alert/:id` (P2)
Полноэкранный алерт при критичном событии. Видео + причина + действия.

### Экран 7: Досье поездки `/trip/:id` (P2)
Хронология поездки: трек, события на таймлайне, видео по клику.
Данные: `track_points` + `track_summary` + v_incidents.

### Экран 8: Восстановление РЭБ `/reb/:id` (P2)
Два трека: официальный GPS (с разрывом) vs восстановленный по CAN.
Данные: `navigation_problem_tracks` — реальные данные уже есть в датасете!
