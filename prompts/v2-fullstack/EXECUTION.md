# EXECUTION — параллельная разработка в ОДНОМ проекте

> Один проект `skai_7`, одна рабочая ветка. Параллельность — через **несколько сессий (вкладок)
> Claude Code в одном окне VS Code**. Источник истины — `00-CONTRACT.md`.

## Почему это работает без конфликтов
Контракт (§5/§7.7) закрепил за каждым треком **непересекающиеся файлы/папки**. Несколько агентов в одной
рабочей папке могут писать **одновременно**, пока трогают разные файлы. Правило: **один трек = одна вкладка**,
две вкладки НЕ работают над одним файлом.

## Владение (что какая вкладка трогает)

| Вкладка/трек | Папки (только свои) |
|---|---|
| **BACKEND** | `api/` (кроме `api/tests/`), `data/seed/`, `data/skai.duckdb` |
| **WEB** | `web/` (кроме `web/**/*.test.tsx`) |
| **TESTS (Codex)** | `api/tests/**`, `web/**/*.test.tsx`, вспом. файлы из `T4` |
| **INTEGRATION** | корень: `Makefile`, `requirements*`, `.gitignore`; роуты `web/src/App.tsx` |

Роутинг (`App.tsx`) и корневые файлы трогает ТОЛЬКО integration (x1/x2) — экраны создают лишь свои `pages/*.tsx`.

## Порядок волн

**Волна 1 (параллельно 2 вкладки):**
- BACKEND: b1→b3 ; b2∥b4 → b5 → b6
- WEB: d1→d2→d3 → f1→f2→f3→f4   (на фикстурах `VITE_USE_FIXTURES=true`)

**Волна 2 (параллельно):**
- BACKEND: b7→b10 ; b8∥b9 ; b11∥b12∥b13
- WEB: d4∥d5 ; f5,f6,f7,f8,f9,f10,f11,f12,f13
- TESTS (Codex, по мере готовности): T1 → T2 → T3 ; T4 в любой момент

**Волна 3 (integration, одна вкладка):** x1 → x2 → x3 → x4

## Коммиты
Работаем на `main` (или заведи `dev`). Коммить часто и по треку: `feat(backend): b3 v_incidents`.
Один трек = одна вкладка → файлы не пересекаются → коммиты не конфликтуют.

## Как гнать промпт
В каждой вкладке: «Прочитай `<путь-к-промпту>` + `00-CONTRACT.md`, выполни; трогай только свои файлы».
Проверяй секцию `## Check` промпта перед следующим.
