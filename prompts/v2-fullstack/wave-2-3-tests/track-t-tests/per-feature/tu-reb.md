# tu-reb · Unit-тесты РЭБ-восстановления (фича #8, модуль b12)

> Трек **Tests** (`feat/tests`, окно 3). Против `00-CONTRACT.md` §7.5.
> **Модель:** 🔵 Sonnet — детерминированная логика против контракта; гейт = pytest.
> **Владеет:** `api/tests/unit/test_reb.py`. Инфраструктура — из `t1`.
> Per-feature слой: гонится, как `b12` лёг на `integration`. Баг → дефект треку B.

## Цель

Покрыть детерминированное выделение разрывов трека `v_reb`/`gap_periods` (`b12`): периоды
`period_type=3` из `navigation__track_periods` + соседние видимые периоды; граничные кейсы.

## Состав — `api/tests/unit/test_reb.py`

- `gap_periods[]` собирает только `period_type=3`; смежные видимые периоды/кадры присоединены.
- Непрерывный трек (нет `period_type=3`) → пустой `gap_periods` / «разрывов нет», не падать.
- `RebRecovery` (§7.5) — поля заполнены для трека с разрывом.
- Нет данных по `id` → детерминированный пустой результат (404 проверяется в `t2`, не здесь).

## Check

- `pytest api/tests/unit/test_reb.py -q` зелёный.
- Кейсы «есть разрыв» и «разрывов нет» оба проверены; пустые данные не роняют.
- Тесты не требуют сети/uvicorn; углубление — в `w3-3`.
