> **Область:** оставшиеся барьеры **x5 (Волна 3) · x6 · x7 · x8 (Волна 4)**. Волны 1–2 и их барьеры
> (x1–x4) уже отработали (P0+P1/P2 в `main`, 88ed8cf) — их не трогаем. Негативы/регресс из аудита
> прошлых волн вынесены в тест-промпты Волны 3 (`w3-3`/`w3-4`).
>
> Источник истины по проверкам барьеров. Каждый `x*`-промпт ссылается сюда и **добавляет** свои
> волно-специфичные негативы. Барьер НЕ зелёный, пока **все** пункты ниже зелёные. Барьер только
> запускает и судит green/red — при провале заводит **дефект треку-владельцу**, код не переписывает.
> Команды — реальные (`scripts/check.sh`, `Makefile`, `make openapi` → `docs/openapi.json`).

## 0. Предусловие + GUARD (до любых проверок)

```bash
cd /Users/dimausac/projects/skai_7 && git checkout integration
MAIN0="$(git rev-parse main)"                          # зафиксировать SHA main ДО барьера (пост-условие §7)
# GUARD: merge берёт только коммиты — стоп при незакоммиченном worktree.
for w in backend web tests; do d=".worktrees/$w"; [ -d "$d" ] || continue;
  test -z "$(git -C "$d" status --porcelain)" || { echo "❌ $w незакоммичено"; exit 1; }; done
```
- Предыдущий барьер зелёный (проверка в каждом x*); слияние волны без конфликтов (`git status` чисто).

## 1. Статика + полный регресс — ОДНОЙ командой (не «только тесты волны»)

```bash
bash scripts/check.sh        # ruff(api,scripts) → pytest -q api/tests → web typecheck → vitest — ВСЁ зелёное
```
- **Это весь набор**, не фич-тесты текущей волны — ловим регресс прошлых волн. Эквивалент: `make check`.
- `make db` **дважды** → идентичные row-counts (ETL идемпотентен, без `Date.now()`/`random`).
- `make openapi` обновляет `docs/openapi.json` без ошибок (OpenAPI валиден).

## 2. API-контракт: коды + схема + НЕГАТИВЫ (для каждого нового эндпоинта волны)

`make api`, затем по каждому эндпоинту:
- **happy:** `200` + схема через `jq` — ключевые поля присутствуют, enum в домене (§3.1/§7.5/§8.4).
- **негатив (обязательно!):** неизвестный `id`/`plate` → **404**; пустой фильтр/набор → `[]` (не `500`);
  битое/неполное тело POST → **422**; не-реализованный домен → как в контракте (`501` или §9/§8).
- **OpenAPI:** `jq '.paths|keys' docs/openapi.json` содержит путь; `jq '[.tags[].name]' docs/openapi.json`
  = ожидаемый набор тегов (число тегов растёт строго на добавленные роутеры волны).

```bash
code() { curl -s -o /dev/null -w '%{http_code}' "localhost:8000$1"; }    # хелпер кода ответа
test "$(code /api/incidents)" = 200
test "$(code /api/incidents/__nope__)" = 404                              # негатив есть всегда
```

## 3. Детерминизм / офлайн-устойчивость

- Любой эндпоинт дважды подряд → **идентичный** ответ (нет `Date.now()`/`random` без seed).
- Без сети/ключей (`unset GROQ_API_KEY` и т.п., VLM/Open-Meteo недоступны) → кэш/детерминированный
  фолбэк, **не 5xx** (контракт §8/§7.3). Для AI-волн — `source ∈ {cache,fallback}` в мете.

## 4. Live ↔ fixtures паритет (фронт)

- Каждый затронутый экран рендерится **и** на живом API, **и** на `VITE_USE_FIXTURES=true` — формы совпадают
  (типы §3.1/§7.5/§8.4). Фикстуры **не маскируют** backend (финальная страховка — nightly live-smoke в x8).
- Состояния **loading / empty / error** у новых экранов; **нет белого экрана**; консоль браузера без ошибок;
  навигация «назад» работает; a11y (focus/aria) у новых интерактивных узлов.
