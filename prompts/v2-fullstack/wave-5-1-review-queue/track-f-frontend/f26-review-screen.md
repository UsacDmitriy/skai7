## Контекст (зачем)

NAV-пункт «Блок валидации» (`/validation`) — сирота: f22 (Волна 4.3) честно пометил его «Будущее,
workflow-движок, будущая волна». **Владелец появился — этот промпт.** По критерию отката из f22:
снять «Будущее», убрать ключ из `COMING_SOON`, маршрут ведёт на живой экран очереди.

## Цель

Диспетчер проходит очередь событий: видит инцидент (есть ли видео-доказательство), подтверждает или
отклоняет с заметкой, фильтрует по статусу — кейс Фомина «39 → 5 подтверждённых» становится workflow.

## Состав

1. **Типы** (`types.ts`, аддитивно): `ReviewItem`, `ReviewQueue` — **дословно по §11.2**.
2. **Клиент** (`client.ts`, за свитчем `USE_FIXTURES`, паттерн соседних методов):
   `getReviewQueue(status?)` → `GET /api/review-queue`; `postReviewDecision(id, decision, note?)` →
   `POST /api/review-queue/{id}`.
3. **Фикстуры** (`fixtures.ts`): `ReviewQueue` с ≥6 элементами — все три статуса, инцидент с
   `video_available:false`, ненулевые `counts`, `evidence_rate: 0.9`.
4. **`ReviewQueue.tsx`** (паттерн таблицы — `Tickets.tsx` f8):
   - шапка: счётчики `pending/validated/dismissed` + «Доказательность: {evidence_rate}%» (§10-контекст);
   - фильтр-переключатель статуса (по умолчанию `pending`);
   - строка: alarm_code, severity-бейдж, ТС, время, чип «видео ✓/—» (`video_available`), статус-чип,
     заметка (если есть);
   - действия в строке для `pending` (и перезапись для решённых): «✓ Подтвердить» / «✗ Отклонить» —
     опциональная заметка (inline-input или prompt-поле), после ответа — обновить список
     (оптимистично или refetch); `stopPropagation` на кнопках (как врезка `/trip` в EventsFeed);
   - клик по строке → `/incidents/{id}` (доказательная карточка);
   - состояния loading/empty/error; пустая очередь по фильтру → «нет событий в этом статусе».
5. **`App.tsx`** (аддитивно): lazy-роут `/validation` → `ReviewQueue`; в NAV у пункта
   «Блок валидации» снять бейдж (живой экран); удалить ключ `/validation` из `COMING_SOON`.
   Комментарий: `// f26: владелец /validation появился — ревизия допущения f22`.
   `/response` НЕ трогать (остаётся «Будущее»).
6. **A11y:** кнопки с `aria-label` («Подтвердить инцидент …»); статус не только цветом.

## Check

- `/validation` рендерит живую очередь (NAV без бейджа, ключа в `COMING_SOON` нет); `/response`
  не тронут (regression f22-теста: обновить ассерт `/validation` — он сменил «Будущее» на живой экран).
- Подтверждение/отклонение меняет статус-чип и счётчики без перезагрузки страницы; заметка видна.
- Фильтр статуса работает; клик по строке ведёт на карточку; кнопки не триггерят навигацию строки.
- Паритет: живой API и `VITE_USE_FIXTURES=true` (все три статуса + кейс без видео).
- `npm run typecheck` зелёный; vitest: рендер очереди на фикстуре, фильтр, наличие кнопок у pending,
  empty/error-состояния; `App.test.tsx` обновлён (живой `/validation`).
