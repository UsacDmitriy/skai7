# Волна 5.1 · Review Queue — очередь верификации событий

Первая под-волна Волны 5 (после барьера x9). Превращает разовую кнопку verify в **workflow
верификации**: каждый инцидент проходит через статусы `pending → validated/dismissed` с видео-
доказательством. Кодим против `00-CONTRACT.md` **§11**. Backend → web ∥ tests.

> **Клиентское обоснование:** Фомин (PepsiCo) — «39 ДТП в телематике, видео подтвердило 5»:
> без очереди подтверждение событий не масштабируется. **Паттерн лидера:** Lytx human-in-the-loop
> review queue (`../COMPETITORS.md`). Инфраструктура готова: журнальный паттерн `actions.csv`,
> `evidence_rate` (§10), эмиттер метрик (b25).
>
> **Почему первая в Волне 5:** самый короткий путь до ценности (`WAVE-5-BACKLOG.md` W5-1) —
> ни одного нового датасета, только сервис + журнал + экран.

| Окно | Промпты | Исполнение |
|---|---|---|
| 1 Backend | `b30` review-сервис + журнал `output/review_queue.csv` + `GET/POST /api/review-queue` | bounded ClinePass · worker · `code` |
| 2 Web | `f26` экран `ReviewQueue.tsx` на маршруте `/validation` (снимает «Будущее» f22 — владелец появился) | bounded ClinePass · worker · `code` |
| 3 Tests | `tu-review` (статусная модель, перезапись, негативы журнала) | bounded ClinePass · worker · `code` |

> **Зависимости:** старт только после зелёного **x9** (нужен `/api/consistency` → `evidence_rate` в
> ответе очереди). `f26` и `tu-review` — параллельно после `b30`.
>
> **Единый статусный словарь (§11.0):** источник истины ревью — ТОЛЬКО `output/review_queue.csv`;
> легаси-экшен `validate` (§3.4, `actions.csv`) не трогаем и не дублируем.

Дальше → **Барьер 5.1** (`../barrier-5-1-review-queue/x10-review-queue.md`) — e2e очереди + полный
регресс → продвигает `main` (паттерн x9).

> Каждый промпт заканчивается секцией `## Коммит` — merge на барьере берёт только коммиты.
>
> ⚠️ **Параллельный коммит без `git add -A`.** `f26` ∥ `tu-review` идут одновременно — `## Коммит`
> каждого стейджит **только свои файлы** (списки = §11.5). Роутер `review` **автодискаверится**
> (`api/main.py:_discover_routers`, модульный `router = APIRouter(...)`) — `api/routers/__init__.py` не трогаем.
