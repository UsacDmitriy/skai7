# f13 · Переключатель ролей и фильтрация по роли (идея #10)

> Трек **Frontend**. Против `00-CONTRACT.md` §6 (AC «Монитор: ролевой switcher»), §7.6 (роль-токены),
> §7.8 (AC «Карта по ролям»). **Владеет:** интеграцией `RoleToggle` (d4) в `EventsFeed.tsx` (f5) и
> `Monitor.tsx` (f6) + сквозной логикой фильтрации по роли (контекст/стор роли + хелперы фильтра).
> Использует примитив `RoleToggle` (d4), UI-примитивы d2 и API-клиент f2.

## Цель

Идея #10 (Маслов, Балтика): одна карта/лента — три роли видят разное. Это **не отдельный экран**, а
сквозная фича: общее состояние роли + правила фильтрации, применяемые в нескольких местах. Плюс
дедупликация ТС (1 `unit_id` = 1 объект, не набор терминалов / не на каждый `AlarmId`).

## Роли

| Роль | Иконка | Что видит |
|---|---|---|
| Логист | 🏭 | только локация/телематика ТС, статус онлайн/офлайн; **без DMS-алармов** (скрыть `source=DMS`), без severity-цветов маркеров |
| Диспетчер | 🛡 | полный доступ: все алармы, видео, телематика, severity-цвета |
| Безопасник | 🔒 | акцент на риск: сортировка/подсветка по `risk_score`, видеоалармы (DMS/ADAS) на первом плане |

## Точки интеграции

1. **Состояние роли** — общий контекст/стор: `web/src/state/role.ts` (или `RoleContext` + `useRole()`).
   Дефолт — «Диспетчер». Значение `Role = "logist" | "dispatcher" | "security"`. Персистить в
   `localStorage` (без `Date.now()` в логике). **Владелец нового файла стора — f13** (согласовать
   размещение с f1, чтобы не пересечься с роутингом).
2. **`RoleToggle` (d4)** — вмонтировать в шапку `EventsFeed.tsx` (f5) и `Monitor.tsx` (f6); chip-токены
   `primary-50/primary` (§7.6). Сам компонент владеется d4 — f13 только использует и связывает со стором.
3. **Хелпер фильтрации** — `web/src/state/roleFilter.ts`: чистые функции
   `filterByRole(role, items)` для ленты (`IncidentSummary[]`) и `markerOptionsForRole(role)` для карты
   (цвет/слой маркеров). Правила:
   - Логист: `items.filter(i => i.source !== "DMS")`; маркеры без severity-цвета, только online/offline.
   - Диспетчер: без фильтра; маркеры по severity.
   - Безопасник: сортировка по `risk_score` desc; DMS/ADAS-алармы в приоритете отображения.
4. **Дедупликация ТС** — `dedupeByUnit(items)`: на карте/в агрегатах 1 `unit_id` = 1 маркер (берём
   последний/наиболее тяжёлый алярм для ТС). Применяется в `Monitor.tsx` через хелпер f13.

> f13 не переписывает страницы целиком — добавляет в них вызовы стора/хелперов и монтирует `RoleToggle`.
> Конкретные правки в `EventsFeed.tsx`/`Monitor.tsx` согласовать с f5/f6 (одни и те же файлы — порядок
> Волны 2 (расширение); f5/f6 оставляют точки расширения для роли).

## Зависимости и параллелизм

- **Опирается на:** d4 (`RoleToggle`, `MapView`/`MarkerLayer` с опциями цвета слоя), f5 (`EventsFeed`),
  f6 (`Monitor`), f2-клиент (данные, фильтрация на клиенте).
- **Бэк:** дополнительных эндпоинтов не требует — фильтрация клиентская поверх `listIncidents()`/
  `listVehicles()`. Работает и на фикстурах.
- **Можно параллелить** частично: новые файлы стора/хелпера (`state/role.ts`, `state/roleFilter.ts`) —
  независимы и пишутся сразу. Интеграция в `EventsFeed.tsx`/`Monitor.tsx` — **после** f5/f6 (общие файлы),
  иначе конфликт. С f9–f12 не пересекается.

## Check

- `RoleToggle` виден в шапке ленты (`/`) и монитора (`/monitor`); переключение меняет роль в сторе и
  переживает перезагрузку (localStorage).
- Роль «Логист» скрывает DMS-алармы (`source=DMS`) в ленте и убирает severity-цвет маркеров (только
  online/offline).
- Роль «Безопасник» сортирует/подсвечивает по `risk_score`.
- На карте 1 `unit_id` = 1 маркер (дедупликация), не на каждый `AlarmId`.
- `filterByRole`/`dedupeByUnit` — чистые функции, покрыты юнит-тестами (детерминированы).
- `npm run typecheck` проходит.
