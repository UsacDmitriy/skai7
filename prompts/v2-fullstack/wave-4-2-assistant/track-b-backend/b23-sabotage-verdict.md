# b23 · Smart sabotage verdict (идея #16)

> Трек **Backend/Data**. Против `00-CONTRACT.md` §8 + §7.5 (`SabotageEvent`). **Владеет:** **аддитивная**
> правка `api/sql/23_v_sabotage.sql` и/или `api/services/sabotage_service.py`.
> **Модель:** 🔵 Sonnet — детерминированное усиление правила; гейт = тесты.
> **Волна 4.2**, окно 1 (backend). Зависит от: существующий `v_sabotage`, b16/b17 (`incident_scene`/`incident_weather`).

## Цель

Усилить вердикт саботажа кросс-проверкой сцены: тёмный DMS + `speed>0` (текущая детекция) **плюс** сигнал
«снаружи день/ясно» из `incident_weather`/`incident_scene` ⇒ выше уверенность подмены/перекрытия камеры.

## Состав

- В `SabotageEvent` (§7.5) аддитивно: `verdict_confidence` (0..1) и `verdict_reason` (что усилило).
- Правило (детерминированное): базовая уверенность из текущего `v_sabotage`; **+надбавка**, если
  `is_day=true`/`api_weather=clear` при тёмном DMS-кадре (камера должна была «видеть»); **−**, если ночь/туман
  (тёмный кадр объясним внешними условиями, не саботаж).
- Обратная совместимость: нет кэша сцены → прежний вердикт, `verdict_confidence` из базовой логики.

## Check

- Тёмный DMS + speed>0 + (день/ясно) → `verdict_confidence` выше, чем при (ночь/туман).
- Нет `incident_weather`/`incident_scene` → прежнее поведение `v_sabotage` (регресс `tu-sabotage` зелёный).
- `verdict_reason` непуст и объясняет надбавку; детерминированно.
