# W3-5 · No-video инцидент достижим в живых данных (empty state + «Запросить архив»)

> Волна 3 · бэклог. Трек **Backend/Data** (владелец `b3`/`v_incidents` + каталог данных),
> **Модель:** 🔵 Sonnet — детерминированная логика/вёрстка против контракта; гейт = секция Check.
> с тест-хуком для трека **T**. Против `00-CONTRACT.md` §1.3/§2/§3.1. **Владеет:**
> `api/sql/10_v_incidents.sql` (и/или источник данных), при необходимости — seed-строка датасета;
> `api/tests/` (хук покрытия). **Не блокирует** P0/P1/P2. **Приоритет средний** —
> закрывает мёртвую UI-ветку P0.

## Контекст (выявлено smoke x3)

UI-карточка инцидента ([`web/src/pages/IncidentCard.tsx`](../../../web/src/pages/IncidentCard.tsx),
ветка `inc.video_available === false`) и панель отчёта (`f7`) реализуют кейс
**«нет видео» → пустое состояние + «Запросить архив»** + поля §2, действующие только для no-video
(`sensor_active_after_sec` — «DMS-сенсор работал +N сек»). Но в **живых данных этот кейс недостижим**:

- `v_incidents.video_available = CASE WHEN a."VideoCount" > 0 THEN 1 ELSE 0 END`
  ([`api/sql/10_v_incidents.sql:25`](../../../api/sql/10_v_incidents.sql#L25));
- источник view — `video_events__selected_video_alarms`, где **у всех 54 строк `VideoCount > 0`**.

Итог: `SELECT video_available, count(*) FROM v_incidents GROUP BY 1` → `(1, 54)`. Ветка empty-state,
`sensor_active_after_sec` и «Запросить архив» **никогда не рендерятся** на бэке-правде → потенциально
мёртвый код, не покрытый ни демо, ни тестами.

## Что сделать

Сделать так, чтобы **хотя бы один** инцидент в `v_incidents` имел `video_available = false`
— детерминированно, без обращения к текущему времени.

Выбрать **один** путь (по согласованию с владельцем контракта):

1. **Естественный (предпочтительно, согласуется с Волной 2).** No-video инциденты приходят из
   невидеосорсов, добавляемых в Волне 2 — `b11` (саботаж), `b12` (РЭБ), сенсорная диагностика
   (`Source=DIAGNOSTIC`, см. W3-2). Если эти источники вливаются в домен incidents через `UNION`
   в `v_incidents`, убедиться, что их строки имеют `video_count=0 → video_available=0`, и зафиксировать
   это контрактом. Тогда W3-5 = проверка + тест на смешанный набор (video / no-video).
2. **Минимальный seed.** Добавить в датасет (`datasets/ready/**`) **одну** детерминированную строку
   алярма с `VideoCount=0` (без `video_files`), чтобы `v_incidents` отдавал no-video инцидент.
   Значения — по аналогии с соседними строками, без новых severity/source вне §3.1.

В обоих путях проверить сквозь сервис:
- `incidents_service.get_detail` для no-video инцидента: `video_available=false`,
  `sensor_active_after_sec` — целое 1..10 (§2, ветка no-video), `cam_*_url` = `null`,
  `cameras[]` длиной 3 со статусами (отсутствующий канал → `offline`).

## Тест-хук (трек T, можно дозакрыть в W3-3)

В `api/tests/test_incidents_api.py` добавить кейс: найти инцидент с `video_available=false`
(или собрать через сервис) → `GET /api/incidents/{id}` → `200`, `video_available=false`,
`sensor_active_after_sec` не `null`; `GET …/video/5` → `404` (видео нет — легитимный 404).
Если путь №1 (Волна 2) ещё не влит — тест помечает `skip` при отсутствии no-video строк
(чтобы не падать до реализации источников), с поясняющим сообщением.

## Check

- `SELECT video_available, count(*) FROM v_incidents GROUP BY 1` → присутствует строка `(0, ≥1)`.
- На фронте `/incidents/<no-video-id>`: показывается пустое состояние видео + кнопка «Запросить архив»,
  блок offline-камеры и «DMS-сенсор работал +N сек».
- Повторный `make db` детерминирован (тот же no-video инцидент, тот же `sensor_active_after_sec`).
- Тест из «Тест-хук» зелёный (или осознанно `skip` до влития источников Волны 2).

## Решение контракта

Если демо-команда решит, что no-video кейс в P0-данных не нужен (он естественно приедет в Волне 2),
зафиксировать это одной строкой в `00-CONTRACT.md` §1.3 рядом с `v_incidents`
(«P0-набор — только видео-алярмы; no-video инциденты появляются в Волне 2 из саботаж/РЭБ/диагностики»),
чтобы пустая ветка не считалась багом, и оставить тест в режиме `skip`-до-Волны-2.
