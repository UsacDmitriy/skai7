# W3-2 · Данные для Source=DIAGNOSTIC (бейдж «⚙ Диагностика»)

> Волна 3 · бэклог. Трек **Backend/Data** (владелец `b1`/каталог данных). Против `00-CONTRACT.md`
> **Модель:** 🟢 Qwen 3.7 max — механическая транскрипция против точной спеки; гейт ловит ошибку.
> §3.1 (changelog #1 (a)). **Владеет:** `data/analysis/alarm_types.json` (каталог типов) и,
> при необходимости, seed-строкой в датасете. **Не блокирует** P0/P1/P2. **Приоритет низкий** —
> кейс нужен только если демо показывает «Камера офлайн» / диагностику.

## Контекст

Changelog #1 (a) ввёл в enum `Source` значение `"DIAGNOSTIC"` — для алярмов сенсорной диагностики
(«Камера офлайн» и т.п.), с бейджем «⚙ Диагностика» на макете 07 (Заявки).
Но в каталоге `data/analysis/alarm_types.json` **нет ни одной строки** с `source:"DIAGNOSTIC"`
и нет кода «камера офлайн». Значит, enrichment (`b2`) и фронт никогда не присвоят `source=DIAGNOSTIC`,
и бейдж «⚙ Диагностика» ни на чём не отрендерится — макет 07 показывает мёртвую ветку.

## Что сделать

1. Добавить в `data/analysis/alarm_types.json` запись типа алярма с `source: "DIAGNOSTIC"`,
   соответствующую кейсу «камера офлайн» (поля как у соседних строк: `raw`, `code`, `label_ru`,
   `severity`, `source`). `severity` — по аналогии с диагностикой (например `medium`/`info`,
   как принято в каталоге; не выдумывать новых severity-значений вне §3.1).
2. Проверить, что enrichment `b2` корректно протягивает `source` из каталога в инцидент
   (маппинг `alarm_type_catalog.source → Incident.source`) — для нового кода ничего особого
   не требуется, но убедиться, что код не отфильтрован.
3. Если демо требует живого инцидента с этим source — добавить **детерминированную** seed-строку
   в соответствующий датасет (`datasets/ready/**`), без обращения к текущему времени.
4. Если решено, что кейс демо-опционален и данных не будет — зафиксировать это в `00-CONTRACT.md`
   рядом с changelog #1 (a) одной строкой («DIAGNOSTIC — зарезервирован, в демо-датасете отсутствует»),
   чтобы бейдж не считался багом.

## Check

- `grep -n 'DIAGNOSTIC' data/analysis/alarm_types.json` — есть хотя бы одна строка **или**
  в `00-CONTRACT.md` зафиксировано, что значение зарезервировано без данных.
- После `make db` (или эквивалента пересборки) инцидент/тип с `source=DIAGNOSTIC` доступен,
  если кейс включён в демо.
- Enrichment не теряет `source` для нового кода (юнит/ручная проверка маппинга).
